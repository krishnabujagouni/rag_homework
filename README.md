# RAG Homework — LangChain + Pinecone

Ask questions about your own PDFs. Two scripts and a config module: one
ingests documents into Pinecone, the other answers questions from them.

## How it works

**Page chunking.** `PyPDFLoader` already returns one `Document` per PDF page,
so a page *is* a chunk — no splitting, no overlap, no `chunk_size` to tune.
Retrieved results map cleanly onto "page 12 of this PDF," which makes
citations easy. The tradeoff is that chunk boundaries follow the PDF's
layout rather than its meaning, and a page break mid-paragraph loses that
context entirely.

**Hybrid search.** Each chunk is embedded twice — a dense OpenAI vector for
semantic similarity, and a sparse BM25 vector for keyword match — and both
are stored on the same Pinecone record. Dense-only retrieval struggles when
a short, specific fact (an address, a figure) sits on a page dominated by
unrelated boilerplate: the fact gets averaged away, and a page that merely
*looks* topical can outrank it. Keyword matching catches those cases.

Pinecone scores both halves in a single dot product
(`dense·dense + sparse·sparse`) and returns one ranked list — this is score
blending, not reciprocal rank fusion. It requires `metric="dotproduct"`;
cosine and euclidean indexes reject sparse vectors.

## Setup

```bash
pip install -r requirements.txt
cp .env.example .env   # fill in OPENAI_API_KEY and PINECONE_API_KEY
```

## Usage

Put PDFs in `data/`, then ingest them:

```bash
python ingest.py
```

This creates the Pinecone index if needed, clears any previous vectors,
fits the BM25 encoder, and upserts every page. Re-run it whenever the
documents change.

Then ask questions interactively:

```bash
python main.py
```

It prompts for a question, prints the source pages it retrieved, and then
the answer. Ctrl+C to quit. It takes no command-line arguments.

## Configuration

Read from `.env`. Two settings are deliberately hardcoded instead: the
source folder (`DATA_DIR = "data"` in `ingest.py`) and the number of
chunks retrieved per question (`top_k=4` in `main.py`).

| Variable | Default | Notes |
|---|---|---|
| `OPENAI_API_KEY` | — | required |
| `PINECONE_API_KEY` | — | required |
| `PINECONE_INDEX_NAME` | `rag-homework` | |
| `PINECONE_CLOUD` / `PINECONE_REGION` | `aws` / `us-east-1` | serverless spec |
| `EMBEDDING_MODEL` | `text-embedding-3-small` | must match `EMBEDDING_DIM` |
| `EMBEDDING_DIM` | `1536` | `-small`=1536, `-large`=3072 |
| `CHAT_MODEL` | `gpt-4o` | |
| `BM25_PARAMS_PATH` | `bm25_params.json` | generated by `ingest.py` |

The dense/sparse mix is left at the library default `alpha=0.5` (even
blend). To favour keyword matching, pass a lower `alpha=` to the retriever
in `main.py`; `1.0` is pure semantic, `0.0` pure keyword. Changing it does
not require re-ingesting — both vectors are stored in full either way.

## Things worth knowing

- **`bm25_params.json` is a build artifact, not config.** BM25 weights terms
  using corpus statistics (IDF, average document length) computed at ingest
  time. `main.py` must load the *same* fitted encoder, or query and document
  sparse vectors end up in different spaces and keyword matching degrades
  silently. Run `ingest.py` before `main.py`; re-run it if the documents change.
- **Changing `EMBEDDING_MODEL` or `EMBEDDING_DIM` recreates the index.**
  Neither the dimension nor the metric can be altered in place, so
  `ingest.py` detects a mismatch, deletes the index, and rebuilds it.
- **Pages with no extractable text are skipped.** Scanned or image-only pages
  produce an empty BM25 vector, which Pinecone rejects — and one such page
  would otherwise fail the entire upsert batch.
